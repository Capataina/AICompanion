# Planning — a node is a pose, an edge is a proven move

What a node is, how edges are generated from what the body can do, the search over them, the path it returns and the bounded reachability questions the senses ask. The mechanism at depth (poses, drops lowered row by row, jump profiles simulated, the edge cache and its invalidation box) is in `../CLAUDE.md`; this file is the map and the seams.

```
Planning/
├─ CLAUDE.md
├─ NavGrid.cs        what a node is: a feet tile where BodyPhysics.Stand finds a pose and no lava is in the column; block, support, liquid, submerged-head, lava-count and platform-underfoot tests over the world interface; the open span beside a lip (its columns and its centre) that a drop is planned across and steered along; FeetWorld, which is the pose's own point (off-centre in a tight column, partway down a slope); and the jump box and drop limits
├─ AStar.cs          the search, and Region, a breadth-first flood over the same edges that returns every feet tile reachable within a budget and whether the region ran out before the budget did (the positioner's reachability tier, the replay tool's third line); neighbours generated on the fly: walk to the next column on the same row, one up or one down wherever a pose exists and can be slid to; drop off a lip by lowering the body itself down the open span, against its left wall, down its middle and against its right wall, to the first surface that holds it, each distinct landing an edge carrying where to steer; fall through the platform underfoot the same way; jump to any node in the box that one of the jump profiles (JumpProfiles: each velocity scale whose apex clears the rise, lowest first, at the walk, half of it and from a stand) lands in, the edge carrying its profile; a drop deeper than the jump box is offered only while AllowOneWayDrops is true (the brain: following, guarding, or saving itself); from liquid every edge costs double and the jump envelope is halved; arriving with the head under water multiplies again; each lava tile in a node adds a flat price, and lava nodes exist only while AllowLava is true (the brain sets it from the companion's life each tick); nodes inside Avoid rectangles (reachable enemies set by the brain each tick, and the navigator's own stuck steps) add a flat price; a search that runs out of budget or region returns a partial path to the closed node nearest the goal; the edges of every tile a search opened are kept between searches (the geometry only, keyed by tile and the lava switch, with the enemy and liquid prices applied on read; a killed or placed tile drops the entries whose scans could have read it, TileChanged, a box a drop deep above it and a jump high below it and EdgeReachX wide; every entry is remade after EdgeCacheLifeTicks for the changes no hook announces; CacheEdges off for the replay's --no-cache); TraceClosed, set only by the replay tool, keeps the closed set for drawing
├─ NavPath.cs        the steps, first first, each with its move kind (walk, jump, drop, fall-through), the tile it leaves from, and what realises it: a jump's velocity scale and start speed, a descent's steer line; and whether the path is partial
└─ Reachability.cs   can a walker/flyer get from A to B; bounded searches that answer "yes" when the budget runs out; the walker search forces AllowOneWayDrops on around itself and puts it back, because an enemy takes any drop and the brain's flag is still whatever the last request set when the senses run
```

The seam that matters is the step: a path step carries everything the follower needs to perform the move the planner proved (the kind, the tile it leaves from, the profile or the steer line), so the follower never re-derives a move from the tiles. Where the follower does re-derive one today (a walk step's own wall jump) is a defect class the traversal work under AIC-177 removes.
