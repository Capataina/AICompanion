# Evaluation separates observation from diagnosis

This folder owns the research's recording census, episode measurements and experimental acceptance criteria. Raw local telemetry is ignored by git; a report is reproducible only while the identified recordings are available. The inventory includes hashes so a later reader can distinguish the same evidence from a similarly named replacement.

```text
Evaluation and Observability/
├─ CLAUDE.md                                      scope and evidence discipline
├─ Recorded Episodes and Measurement Limits.md    raw observations and qualified interpretations
├─ Recording Inventory and Reproduction.md        corpus identities and read-only analysis recipes
├─ Experiments and Recorder Requirements.md       discriminating tests and observability changes
├─ Proposal 1 Failure Cases and Diagnostic Contracts.md  prospective failure matrix, plain flows and HUD evidence
├─ Behavioural Acceptance Matrix.md               positive and countercases for all README responsibilities
├─ Question Answers and Remaining Evidence.md    dispositions for all 140 research questions
└─ Research Scope and Verification.md             obligations, checks, corrections and reproducibility limits
```

A sampled activity name is not a fresh decision, a route status is not a physical outcome, a tool call is not productive work, and a retained failure is not a new failure on every row. Count events by identity and state changes by transition. Interpret each timestamp against its producer's clock. Experiments must fix these meanings before they compare architectures, because a wrong measuring rule can make a working mechanism look broken and a broken one look successful.

Implementation changes described here remain proposals. No runtime recorder, report generator or fixture was changed or executed for this research.

The Proposal 1 failure analysis adds ten top-level, nine family and forty-five activity cases, each with a likely owner, a shared remedy and discriminating evidence. Its elevation-and-ore example is an owner-reported symptom, not a native reproduction. It separates useful job value from failed execution, and movement-purpose targets from immediate firing targets. The proposed family/activity health-bar labels consume the same activity evidence as the inspector.

The purpose-family follow-up extends E04 with parent/child offer consistency and a separate shared-executor comparison, and E14 with explicit reunion and accumulated-detour cases. The question ledger preserves its earlier evidence dispositions with a supersession link to the current proposal direction; a changed architectural preference does not rewrite old recordings.
