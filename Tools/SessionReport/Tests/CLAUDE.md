# Tests — synthetic validation of readers and checks

The real parser and chronology reader are driven against synthetic records that exercise all the edge cases a real session could produce. `ChronicleTests.cs` builds these fixtures from declared timestamps, state transitions and occurrence payloads, then verifies they parse and coalesce correctly.

```
Tests/
├─ ChronicleTests.cs    synthetic fixtures for parser, state intervals, event ordering and check validation
└─ PlayMeasureTests.cs  every play measure against a real capture, with the number it must produce
```

**Both halves file a ledger row, and the reason is that they did not.** A red self-test used to print its failures, return 1, and contribute nothing the run file could hold, so `verify.sh` scored a run whose reader's own tests were failing and exited 0 — demonstrated by pointing `AIC_PLAY_CAPTURE` at a capture the pinned numbers cannot match, which produced "23 of 25 pinned numbers did not reproduce" and exit 0. The chronology half builds its own fixtures and is wrapped in `EmitLedgerRows.Case`; the measures half files its own row instead, because `Telemetry/` is gitignored and so "could not look" is the ordinary outcome in a fresh checkout, which `Case` can only turn into a pass. A pass row for a run that read no capture would make an unverified instrument indistinguishable from a verified one on every scoreboard afterwards, so the absent capture is a `skipped` row carrying the path it wanted.

**The measures half pins the first orb play, by name, for the stillness, distance, smoothness and safety measures only.** The capture is `Telemetry/2026-09-15_08-30-31-684.tsv`, named rather than resolved as the newest in the folder, because the pins are facts about that one recording and the next playtest would otherwise become the default and turn them red. The other measures run on it unpinned, and the walker pins they once had are gone with the body. Three paths still skip rather than pass: an absent capture, which is every agent worktree because `Telemetry/` is gitignored; an empty pin table; and a capture below schema 0.34.0, because an old capture carries every column name a measure asks for and would produce confident numbers about a body the game does not have — pointing `AIC_PLAY_CAPTURE` at the 13:27 capture of 14 September prints that skip with `0.32.0` in it.

**The capture cannot prove the rules it has no instance of, so a fixture does.** Every tick of the pinned capture is consecutive, so a stillness or smoothness measure that ignored gaps in the ticks would reproduce every pin. `StillnessAndMotionPairsBreakAtAGapAndAtDeath` builds rows with a gap, a dead stretch and a downed tick, and asserts the numbers that move when either rule is dropped: a second run appears, the p90 distance jumps to a dead row's, and the heading set grows from one straight pair to three.

**Two fixtures here pin a producer rather than a reader, and they are the ones that fail loudly when the recorder moves.** `RecorderChronologyContractUsesActualLifeColumn` asserts the body line, the route line and the steering's requested velocity as literal header substrings, and asserts that no walking-body column has come back without a check that reads it. `AClaimedArrivalMustLieInsideItsSuccessRegion` pins the navigator's arrival radius, the reach box extents, the eye height being zero, the region names, and that the recorder judges an arrival on the orb's centre. Both exist because a producer rename is otherwise invisible: a reader addressing a column nobody writes reports a clean run it never measured.

**A fixture built to fail if the check reads the wrong column is worth more than one built to pass.** The frozen-body case sets `npc_vel` to zero and `desired_vel` to 2 px a tick — the exact record a body pressed into a wall writes, because the motor sets the NPC's velocity from the displacement the circle contact allowed — and asserts the *grade* rather than the presence of a finding, so a check reading the contact's allowed velocity for "driven" returns Potential and goes red. The follow-arrival case is the mirror: it asserts that a body parked on its request's anchor and far outside the admitted region fires, because acceptance stopped widening to the anchor and a check still admitting it would pass a silence assertion.

**The follow-progress fixtures are a pair, and neither is worth anything without the other.** One is a body closing 4 px a tick along a single smoothed segment with its route index flat, which must stay silent; the other is a body that never moves under a replan that halves the remaining distance, which must fire. Run either alone and a rule can pass it by ignoring the signal the other tests, which is exactly how the index-only rule looked correct on the walker's fixtures. Every other fixture in that method holds `route_remaining_px` constant on purpose, so its firing is earned by the absence of both signals rather than by the one the walker happened to have.

A fixture is made from the schema version it needs to test. `TravelEvidence.First` is the gate that decides whether new checks fire on new captures (they skip until real data exists to grade them), and the fixtures derive their declared schema from that gate — the ones that should run read the current gate value, the one that should skip reads a minor below it. That ensures that as the schema advances, the tests still run the right tests: old checks still test against old data, new checks wait for new data, and the skip fixture keeps validating that new checks correctly skip old captures. Damaged captures, truncated rows, malformed identities and closed-capture metadata are all tested here so that the readers refuse to report Definitive for them and instead report the reduced coverage.

Run with `dotnet run --project Tools/SessionReport -- --self-test`.
