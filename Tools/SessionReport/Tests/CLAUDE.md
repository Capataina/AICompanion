# Tests — synthetic validation of readers and checks

The real parser and chronology reader are driven against synthetic records that exercise all the edge cases a real session could produce. `ChronicleTests.cs` builds these fixtures from declared timestamps, state transitions and occurrence payloads, then verifies they parse and coalesce correctly.

```
Tests/
├─ ChronicleTests.cs    synthetic fixtures for parser, state intervals, event ordering and check validation
└─ PlayMeasureTests.cs  every play measure against a real capture, with the number it must produce
```

**The section profile has a synthetic fixture and no pinned capture yet**, because no played capture is at schema 0.48.0: `TheSectionProfileIsReadAndAnOlderCaptureDeclinesByName` builds 200 rows whose every expected share is arithmetic a reader can do by hand, a sidecar with one `cost-spike` tree, and a 0.47.0 capture that must be declined by name, and pins the recorder's column names and the occurrence's fields by literal. Reading the fence's dash as a zero fence reddens it (12 spikes instead of 2), and so does removing the schema gate. The first 0.48.0 play is the capture to pin next.

**`ExplainingATickPrintsWhatTheRecordHoldsAndNamesWhatItLacks` writes a five-tick capture in which every value is distinctive, so each line `--explain` prints can be traced to the one cell or occurrence holding it.** Its decision's numbers sit on a settled payload at tick 4 and its release on an unsettled one at tick 5, as the producer writes them; the newest `decision` occurrence names no leader, as most real ones do not; a hostile is spawned with a slot, damaged under its spawn identity with none, and killed; and the capture carries no frame, profile, allocation or fence column, so all of them must appear on the closing absent line and `npc_px` must not. Three mutations each redden it on their own assertion (24 September 2026): reading the numbers off the span's last payload rather than its settled one ("read the decision's numbers off the wrong record"), dropping the subject-to-slot map for damage records ("did not place the damaged hostile by its spawn's slot"), and no longer remembering an absent column ("did not name frame_ms in its closing absent line"). The explanation and its window form are also driven over every damaged variant in `ADamagedCaptureReducesCoverageAndInventsNoContradiction`. A fourth mutation, calling every placed NPC hostile, reddens it on "did not count the censused zombie as the one hostile", because the fixture's bunny is spawned and never censused.

**The PNG writer is checked against the format's own constants before it is trusted to check itself.** `APngRoundTripsThroughAStandardInflateWithEveryCrcRight` first holds the CRC to the published CRC-32 check value (`"123456789"` → `CBF43926`) and the IEND chunk's fixed CRC (`AE 42 60 82`), and only then decodes a 3×2 image the long way — signature, every chunk's CRC over its type and data, IHDR's fields, the IDAT inflated by `ZLibStream`, filter byte 0 on every scanline — and requires the pixels back exactly. The order matters: a decoder that verifies chunks with the writer's own CRC would pass a writer whose CRC table is wrong, which is the mutation the check value exists for. Three mutations each redden it (24 September 2026): the CRC over the data without the type ("the IHDR chunk's CRC does not cover its type and data"), the unreflected polynomial ("check value FC4F2BE9, expected CBF43926"), and no filter byte ("the inflated image is 18 bytes, expected 20"). `ATickPictureDrawsWhatTheRecordPlacedAndLeavesTheRestUnknown` draws a synthetic tick whose one sixteen-tile snapshot is air above row 34 and rock from it, and reads pixels back through `DrawTickPicture.MapLeft`, `MapTop` and the summary's origin and scale: the orb's centre, a known rock tile, a known air tile, a tile no snapshot reached, the region's left edge and a censused hostile each have one right colour, and the known-tile count must be the snapshot's 256. Painting an unknown tile as rock reddens it. The same group requires every character the picture writes to be a glyph of the font and a missing glyph to look like no digit, because the first world-run picture printed its terrain note's semicolon as the font's hollow fallback box, which is the digit zero; restoring that box reddens it ("a character the font lacks is drawn exactly like a digit"), and so does removing the semicolon glyph. The damaged-capture group also draws a picture of each variant, where an `InvalidDataException` naming what is missing is the only allowed alternative to a picture.

**Both halves file a ledger row, and the reason is that they did not.** A red self-test used to print its failures, return 1, and contribute nothing the run file could hold, so `verify.sh` scored a run whose reader's own tests were failing and exited 0 — demonstrated by pointing `AIC_PLAY_CAPTURE` at a capture the pinned numbers cannot match, which produced "23 of 25 pinned numbers did not reproduce" and exit 0. The chronology half builds its own fixtures and is wrapped in `EmitLedgerRows.Case`; the measures half files its own row instead, because `Telemetry/` is gitignored and so "could not look" is the ordinary outcome in a fresh checkout, which `Case` can only turn into a pass. A pass row for a run that read no capture would make an unverified instrument indistinguishable from a verified one on every scoreboard afterwards, so the absent capture is a `skipped` row carrying the path it wanted.

**The measures half pins the first orb play, by name, for the stillness, distance, smoothness and safety measures only.** The capture is `Telemetry/2026-09-15_08-30-31-684.tsv`, named rather than resolved as the newest in the folder, because the pins are facts about that one recording and the next playtest would otherwise become the default and turn them red. The other measures run on it unpinned, and the walker pins they once had are gone with the body. Four paths skip rather than pass: an absent capture, which is every agent worktree because `Telemetry/` is gitignored; an empty pin table; a capture below schema 0.34.0, because an old capture carries every column name a measure asks for and would produce confident numbers about a body the game does not have — pointing `AIC_PLAY_CAPTURE` at the 13:27 capture of 14 September prints that skip with `0.32.0` in it; and **a capture nobody played**, because `../../WorldRun` drives the mod's own recorder and its output is a playtest's format in every respect but the `# synthetic=` preamble line. That last one is the healthiest-looking of the four: pointed at a world run of the very capture the pins came from, the measures run to the end and produce a full set of numbers about the harness. Measured with the skip removed and `AIC_PLAY_CAPTURE` on a marked copy of the 22 September capture, 16 of 17 pins failed — loud, but loud about the wrong thing, and a world run of the *pinning* capture would have been quiet and wrong instead.

**The capture cannot prove the rules it has no instance of, so a fixture does.** Every tick of the pinned capture is consecutive, so a stillness or smoothness measure that ignored gaps in the ticks would reproduce every pin. `StillnessAndMotionPairsBreakAtAGapAndAtDeath` builds rows with a gap, a dead stretch and a downed tick, and asserts the numbers that move when either rule is dropped: a second run appears, the p90 distance jumps to a dead row's, and the heading set grows from one straight pair to three.

**Two fixtures here pin a producer rather than a reader, and they are the ones that fail loudly when the recorder moves.** `RecorderChronologyContractUsesActualLifeColumn` asserts the body line, the route line and the steering's requested velocity as literal header substrings, and asserts that no walking-body column has come back without a check that reads it. `AClaimedArrivalMustLieInsideItsSuccessRegion` pins the navigator's arrival radius, the reach box extents, the eye height being zero, the region names, and that the recorder judges an arrival on the orb's centre. Both exist because a producer rename is otherwise invisible: a reader addressing a column nobody writes reports a clean run it never measured.

**A fixture built to fail if the check reads the wrong column is worth more than one built to pass.** The frozen-body case sets `npc_vel` to zero and `desired_vel` to 2 px a tick — the exact record a body pressed into a wall writes, because the motor sets the NPC's velocity from the displacement the circle contact allowed — and asserts the *grade* rather than the presence of a finding, so a check reading the contact's allowed velocity for "driven" returns Potential and goes red. The follow-arrival case is the mirror: it asserts that a body parked on its request's anchor and far outside the admitted region fires, because acceptance stopped widening to the anchor and a check still admitting it would pass a silence assertion.

**The follow-progress fixtures are a pair, and neither is worth anything without the other.** One is a body closing 4 px a tick along a single smoothed segment with its route index flat, which must stay silent; the other is a body that never moves under a replan that halves the remaining distance, which must fire. Run either alone and a rule can pass it by ignoring the signal the other tests, which is exactly how the index-only rule looked correct on the walker's fixtures. Every other fixture in that method holds `route_remaining_px` constant on purpose, so its firing is earned by the absence of both signals rather than by the one the walker happened to have.

**The player-reference checks are found through the report's own evaluation, and the silence cases are asked of the check directly.** `ThePlayersReferenceChecksFindWhatTheyClaim` loads its positive captures through `Program.Evaluate`, so a check dropped from the registry turns it red as surely as a check that stopped finding; each silence case changes the one fact its rule turns on — a lit tile, a stretch too short, the companion lighting, a tile that keeps moving; a hostile too far, a walking player, a hunt not usable — and asks the check itself, so a red there names the rule rather than the registry. `TheFunnelSectionTalliesEachActivity` pins the description's funnel line as a literal.

A fixture is made from the schema version it needs to test. `TravelEvidence.First` is the gate that decides whether new checks fire on new captures (they skip until real data exists to grade them), and the fixtures derive their declared schema from that gate — the ones that should run read the current gate value, the one that should skip reads a minor below it. That ensures that as the schema advances, the tests still run the right tests: old checks still test against old data, new checks wait for new data, and the skip fixture keeps validating that new checks correctly skip old captures. Damaged captures, truncated rows, malformed identities and closed-capture metadata are all tested here so that the readers refuse to report Definitive for them and instead report the reduced coverage.

**The run's own group count is derived from what asserted, never written down, and the reason is a failure a literal cannot catch.** The printed count was a literal reading 44 against 46 real groups — stale twice over — and the staleness is the smaller half of the problem: a literal is equally happy whether a group is missing from the print or missing from `Run`, and **a group written and never wired into `Run` reads as coverage in the file and executes never**. `Require` records its caller now, the run prints the groups that actually asserted something, and it names any declared group that asserted nothing (`c16fe4d`). So a group whose assertions all became unreachable is a named line rather than a silently smaller number, and the count in this paragraph is deliberately absent — the run prints it.

**`FindingsFoldToOneLinePerClassCarryingItsCount` is the only group here that tests the report's arithmetic rather than a check's**, and its three arms are the three ways a fold goes wrong. Three hundred occurrences of one class must print one line whose count is three hundred and whose span is the whole of it; two occurrences of one class must stay two lines, because two paragraphs of real numbers beat one paragraph of a count; and ten genuinely different classes from one check must print six and a tail, so no check can flood a report however many distinct things it finds. Beside them two arms pin the default class itself — two titles differing only in a number are one class, two differing in a name are two — because that masking is a heuristic and the checks whose digits are *identities* rather than measurements have to declare a `Finding.Class` instead.

**`ACensusAdmissionMustSurviveItsOwnBinder` pins three producers before it tests anything**, because the check it covers rests on two refusal literals and a domain set that live in three other folders, and a reader whose table drifts from its producer reports a clean run for ever. The literals are read out of `CombatCourseOpportunity.cs`, `BindAssistanceOpportunity.cs` and `AuditDecisionContracts.cs` by path. That pin is the one arm here proven by mutating a *producer* rather than the reader: renaming the assistance binder's refusal to `assistance-target-unobserved` and rebuilding reddens it with "the assistance binder no longer refuses `assistance-target-unresolved`". Its six join arms are each a way the join goes wrong — an admission and a refusal in one record against an admission carried forward, a census with nothing usable, a refusal reason no binder in the table owns, two assistance domains usable behind one refusal, the 0.45.0 tripwire agreeing and the same tripwire naming a domain this reader found nothing in.

**Every page the ordinary report prints goes through `ADamagedCaptureReducesCoverageAndInventsNoContradiction`, and a new one is not covered until it is added there.** That group damages one consistent capture five ways — killed mid-write, corrupt, respawned, old, unopened sidecar — and drives every reader over each; a page that throws on a cut row takes the whole report down, and a damaged capture is the ordinary case rather than the exotic one. The course timeline and the behaviour parity table were added to it in the same commit as themselves, because a page reached only from `Program.Main` is reached by nothing in the self-test otherwise.

**`TheBehaviourParityTableStillNamesRealBehavioursAndRealFixtures` is the group that caught its own uselessness.** It pins the parity table's two claims about files outside this folder — that every behaviour it maps is still a row in the README's specification, and that every fixture case it names is still registered by some instrument — because both can rot without changing a single number in a report, which is the failure a coverage table exists to prevent and would otherwise commit itself. The second pin searched all of `Tools/` for each case literal and passed a mutation that invented a case outright, because the table's own literals live under `Tools/SessionReport/Write/` and the search was finding them: **a pin that includes the thing being pinned asserts that a file contains its own contents.** It excludes this tool's tree now, and the same mutation reddens.

**`TheCourseTimelineIsOneRowPerDecisionAndFoldsWhatRepeats` is six ticks long and every one of them is there to break a join.** Its first decision is retained over three ticks and traces its payload on the second, so a lookup keyed on `choice_tick` finds nothing for it; its second decision traces nothing at all, so a fold treating that absence as a value would split the table; and its third says exactly what the first said under a census that has moved, so a fold ignoring the census would merge two different situations. The row-count assertion counts every data line rather than the two it expects to see, which is the correction that made it discriminate — the first version counted lines beginning with the two tick numbers it knew about and passed under a mutation that printed three rows.

**`ASyntheticCaptureIsNotReadAsPlay` carries the world run's real marker verbatim, and that arm exists because every synthetic fixture passed while the real one did not.** The note in `AttachTheRecorder`'s line runs to the end and has a semicolon inside it — "nobody played this; it is the world run replaying…" — so a parser splitting the whole value on `;` and calling any segment without an `=` the producer printed half that sentence as the name of the harness. A fixture written from the format's description rather than from an instance of it would have missed that, and did; the arm now pins the string the producer writes.

**`TheCourseErasChecksReplaceTheChoosersAtTheirSchema` takes its skip arms through `Program.Evaluate`**, for the reason the revived combat check's coverage arm does: asking the check whether it would skip proves nothing about the runner that has to skip it. Its fixtures differ only in their `# schema=` line, which is the point — both columns it turns on kept their names and positions when the course brain took them, so the schema line is the only witness there is, and a fixture pair that changed a column would be testing something the capture cannot show.

**`TheRetiredChooserColumnsDeclineByNameAtTheirSchema` is the ceiling case, and it is the one every gate in this tool was blind to before it: a removal rather than an addition.** Every other schema gate here is a floor — `SchemaAtLeast`, "is this capture new enough to carry the evidence" — which answers yes to a 0.46.0 capture for every question ever asked of it, including the ones whose evidence 0.46.0 is exactly what `AIC-419` removed with the family chooser. The fixture drives a synthetic 0.46.0 header (200 rows, because the players-reference check wants three seconds of an idle player before it says anything, and a fixture shorter than its own threshold proves only that a check can stay quiet) with a decision occurrence carrying a census admission and no `factors:` entry, and asserts three different right answers from three readers: `MeasureHuntKnownUnusableShare` declines by name rather than publishing a zero share (`Measures/CLAUDE.md` carries why); `HuntsWorthTakingAreTaken` keeps running — its offer, raw and final columns all survive 0.46.0, only `_time` and `_funnel` went — and names both retired decorations inside its finding rather than dropping them from the sentence silently; and `DescribeSession`'s funnel line says "retired at schema 0.46.0" once rather than a `foreach` over absent columns silently emitting nothing. A fourth arm plants a `combat_funnel` column back into a 0.46.0 header and asserts the real column is shown rather than the retirement notice, because the notice is what the reader says when the column is absent and must never stand in front of a present one. Three mutations prove it, each red on its own assertion: the measure's decline removed reports a share of zero on a row whose direction is "down"; `combat_funnel` planted into the header without removing the notice text prints no funnel line at all; and `SchemaBelow` returning true unconditionally fails to separate a 0.46.0 capture from a 0.44.0 one, reddening the group's own guard assertion first and masking everything downstream — the narrow mutation on the measure is the one that actually proves the measure's own gate.

**`CheckTheFrame` and `MeasureTheFrame` share one guard, and a dropped row is what it exists for.** `frame_ms` is anchored at `PostUpdateEverything`, so a row written inside update N carries the interval that closed at the end of update N−1, and the brain cost inside that interval is the *previous* row's — both readers therefore require `i > 0 && session.Tick(i) == session.Tick(i - 1) + 1` before attributing a pair, because the previous *line* of the file and the previous *update* are the same thing only until a row is dropped or a tick is skipped. The frame group's fixture is the phase fixture with its middle row removed (ticks 0 and 2 survive): without the guard, row 2's interval is wrongly credited with tick 0's brain cost and reads **80%** off a pair that spans a missing update; with the guard there is no attributable pair and the share reads 0 over an empty set, stated as "0 of 1 measured row(s)" rather than as a bare zero, because excluding a pair changes what a zero share means and a silent exclusion is the same class of defect as the wrong attribution it replaces.

**`TheGuideQuotesTheSchemaConstantItDocuments` also refuses any `N of M checks ran` literal anywhere under `Tools/SessionReport/`, by regex over every `CLAUDE.md` in the tree.** Two such sentences were found wrong in one file at once — one introduced by the very change whose subject was false coverage output, the other stale for long enough that nothing dated it — which is two instances of one shape and the tell that a reader will write a third. Both numbers in that line move for reasons no guide sentence can outrun: the denominator with every check the tool gains, the numerator with every schema a capture predates. The message names why the figure cannot be quoted rather than asking for it to be updated, so a folder guide describes which checks skip and why, and points at the run for the count.

Run with `sh Tools/build.sh session-report` then `dotnet Tools/SessionReport/bin/Debug/net8.0/SessionReport.dll --self-test`. `dotnet run --project` does not work here — `UseAppHost=false` leaves no launcher for it to start — and every command line in these guides that said otherwise was wrong from the day it was written.

The course snapshot fixture first reads a complete writer-format JSON snapshot successfully, then changes one property at a time: a missing value, null or non-object snapshot, sequence gap, null manifest entry or key, wrong value digest, duplicate expected or captured key, source tick that disagrees with the event, modified scheduler or policy, unsupported payload version, absent terminal status, timeout, or wrong terminal row count. A clean terminal line followed by a corrective incomplete line must remain incomplete. Every variant uses a fresh file stem so the sidecar cache cannot hide its change. A test that expects only partial coverage without first establishing the complete control can pass because its supposedly good event already disagrees with its snapshot; the phase's case is one way to make that mistake.
