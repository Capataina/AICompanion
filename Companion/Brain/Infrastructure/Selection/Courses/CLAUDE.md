# One owner publishes a concrete course and repairs its conditional future

This game-free core models a revisable sequence of physical effects. The course owner publishes one immutable revision only after its prefix validates; the existing activity owner still controls native execution. A speculative suffix cannot change grants. Useful effects and future harm/gap share the canonical plan's dimensionless discounted policy, with the base resting region traversal as its fixed episode time scale. This is an explicit product preference, not a derived universal exchange rate.

```text
Courses/
├─ CLAUDE.md                    model and publication boundary
├─ DescribeCourse.cs            immutable bindings, effects, resources, estimates and receipts
├─ CompareCourseOutcomes.cs     frozen-census objective, bounds and boundary comparison
├─ MeasureCompanionshipGap.cs   the shared rectangular gap and captured-preference pull curve
├─ ForecastCompanionshipGap.cs  frozen region travel and piecewise companionship intervals
├─ ForecastCourseCompanionship.cs resumable bound-course and return-leg costs with input provenance
├─ ForecastContactHarm.cs       repeated hits at the game's own immunity cadence, truncated by predicted kills
├─ ProjectCourseEffects.cs      sparse hypothetical state and once-only physical allocation
├─ ReadCourseTravel.cs          captured native route timing and arrival momentum, read through manifests
├─ RequestEnemyCourseMotion.cs  typed enemy-model requests naming generation, horizon and model revision
├─ SampleContactTrajectory.cs   budgeted contact boxes from the shared coarse course timeline
├─ TrackCourseDependencies.cs   tracked fact manifests and reverse dependency index
├─ RepairCourse.cs              resumable transitive dirtiness without partial publication
├─ RetainCourse.cs              one current course, semantic boundaries and atomic revision
├─ BindCourseOrder.cs           frozen sequential binding, resumable application and consequence handoff
└─ SearchCourseOrders.cs        insertion/removal/exchange and spatial alternatives
```

`DecisionFactSnapshot` is immutable observed input. `TrackedFactReader` records even absent facts; bindings must declare every read, so missing replay inputs cannot masquerade as an empty world. Predicted successor deltas stay in `ProjectedCourseState` and record their parent effects. A binder checks `HasUnresolvedChange` before consuming a fact that an uncertain predecessor would alter: falling back to the original observed value would erase that predecessor's possible effect. Native receipts allocate actual physical amount once; a predicted torch placement alone cannot certify permanent coverage.

A derived query may finish after the observation freezes. `IsModelExtensionOf` admits only additional modelled or unresolved answers with the same snapshot identity, world, tick, observation ordinal and receipt watermark, and with every previous fact unchanged. `SearchCourseOrders.ExtendModelFacts` delivers that extension to the suspended projector without restarting its domain cursor or recreating earlier bindings. New observations, changed existing answers and a changed clock require the ordinary new-snapshot/revalidation path. Freezing observed state must not prevent a query about that state from ever finishing.

Bindings and effects occupy one globally unique identity space. `CourseDependencyIndex.Build` registers a binding before its effects, with each effect depending on its owner and its declared causal predecessors. A later binding that reads a hypothetical value names that effect as a parent. The effect's own fact reads enter the same reverse index, so a changed enemy pose can dirty a projected impact and every use enabled by that impact. A read journal belongs to one binder invocation; inheriting previous invocations' reads would invent dependencies. An enabling delta becomes available at its finite justified latest time, and a child's earliest effect cannot precede that bound. A nominal-only prediction may contribute nominal value, but cannot certify a causal successor. Checking nominal times alone would turn an expected early hit into a guaranteed shove before the parent model promises it.

The projection checks the physical resources before changing branch state. Every body phase shares one body and every hand phase shares one hand, regardless of the caller's pool name. Body and hand reservations fit the binding's absolute projected interval; mana and cargo retain their separately keyed capacities. Publication repeats projection validation rather than trusting a binder's success label. A consumable capacity is a captured `capacity` fact whose identity is the pool key, and the binding declares that read. Its reservation may end only when modelled restoration or disposal makes that capacity available again; interval non-overlap alone cannot establish replenishment. This restoration contract remains an integration obligation for the concrete producers. Repeating the same binding object changes nothing; a different object reusing its identity is refused.

At a native execution boundary a legal nominal continuation may win without waiting for calibrated certainty. Between boundaries an admitted current prefix survives overlapping or absent comparison bounds; proven improvement or required repair can replace it. Route waypoints never create execution boundaries. Past flight and delivered effects do not enter a remaining-future comparison. Different target partitions conserve original needs. Slot reuse is a different generation.

Re-observation may refresh forecasts for the same accepted uses in the same order. It cannot remove a prefix, exchange steps or change the concrete method, tool or pose. Those changes go through publication and its comparison. A dependency traversal that has not finished cannot be erased by publishing a partial repair; once it finishes, every retained binding and effect must have complete, current inputs before the replacement graph becomes visible. The next native use validates against realised facts; later uses remain conditional on their earlier effects.

Damage and companionship costs carry numerical forecast ranges when their models can justify them. A model label without those ranges stays uncertain and cannot certify strict superiority. Native exact costs use their observed points; bounded damage pairs its minimum with the latest impact and its maximum with the earliest impact. Encounter interruption additionally requires the challenger's upper self-harm bound not to exceed the incumbent's lower bound. An unresolved tail also makes companion self-harm unresolved: an empty finite hit list cannot certify zero harm in an unknown future. The frozen census must be complete before the objective claims justified bounds.

Consequence publication distinguishes a recorded unresolved answer from an absent input. A current cost manifest may contain unresolved model facts only when the projection exposes its unresolved tail; stale or missing facts still refuse publication. This permits a legal first choice with fallible future estimates instead of waiting for impossible certainty. Binding admission, resource proofs and enabling effects retain the stronger complete-manifest contract, so uncertain costs cannot make an unproven native use executable.

Receipt deduplication retires behind a completed issued-ID floor supplied by the observation owner. That floor advances only after all earlier native dispatches have completed, which matters when a nested hit finishes before the outer hit. Replaying a retired receipt remains a duplicate without retaining every old ID; only live effects keep confirmation entries. World reset removes the floor as well as every course and receipt identity.

Executable uses and dispatched physical effects have separate lifecycles. `ObserveExecution` advances the prefix only at an observed completed use, retaining only the effect IDs the native dispatch actually issued. The owner keeps these effects through release and replacement, so choosing to follow the player cannot despawn a projectile or reset its partial hit allocation. The projection carries outstanding effects and completed causal roots independently of `Steps`; the dependency graph can therefore retain an impact while a different binding executes. Physical forecasts retain their original observation-time origin and are rebased into each later snapshot instead of restarting their flight clocks. A native terminal observation ends their lifetime; an overdue unresolved impact cannot certify a successor. The next comparison after executor advancement requires a fresh remaining projection.

Search keeps its pending order and projection cursor across budget cuts. Pending projections expose travel and enemy-motion requests to the observation owner; each completed model answer extends the same frozen catalogue before projection resumes. Enemy request identity includes slot, generation, horizon and model revision, so another prediction law cannot reuse an older answer. A missing captured enemy produces unresolved model evidence rather than a live lookup or endless pending request. Suffix depth is a storage/work bound; each observed site still receives a seed and a spatial alternative. The projector must price consequences after prior effects, prove native resources and expose unresolved tails. An empty order means companionship with its own projected costs, not an artificial zero-cost idle.

`BindCourseOrder.MissingTravel` forwards the suspended domain binder's requests to the observation's model-query owner. The domain cursor remains on the candidate needing that answer; completing a query must resume that candidate rather than discover that enumeration already skipped it. Starting another order clears the former order's requests.

Pending projection results carry travel requests through `SearchCourseOrders.RequiredTravel`, including requests emitted by a consequence provider. Terminal projection results clear them. The native observation owner drives request scheduling and model-only extensions; the pure search never reads terrain or creates another computation allowance.

`CourseProjection.ConsequenceDependencies` records the facts behind whole-course harm, companionship and reunion costs. Its separate graph node depends on the trajectory's bindings and effects; a changed cost-only fact dirties that node without revoking an otherwise legal native use. Publication requires those reads to remain complete and current. Physical-effect reconciliation and observed execution advancement preserve the manifest, so neither operation silently discards cost provenance. An empty manifest represents a calculation with no captured inputs; concrete consequence providers must supply every input they consume.

`ForecastContactHarm` consumes captured per-tick contact boxes, actor life and readiness, and effective damage per actor. It scans contacts under the shared allowance, in native hostile-slot order, and reports predicted hits for each actor as nominal harm. Missing geometry, unsupported geometry and an incomplete hostile census keep the tail unresolved. Missing geometry never means safety. The native producer must supply actual contact shapes rather than assuming every enemy uses its visual box, and must carry these inputs into the whole-course consequence manifest.

**It prices a threat that keeps hitting, since 21 September 2026, and until that date pricing one hit cost a whole behaviour rather than a number.** A hit used to end that actor's scan, on the honest grounds that immunity, knockback and hit hooks needed a successor model before a second overlap could be a second hit. Measured on `danger lifts combat over work` — a real zombie walking into a forty-life player — that produced harm `0.3500` on mining, on fighting and on standing still alike: the zombie reaches him about thirty ticks in and no course kills it first, so one hit lands whatever the companion does and **there was no term in which the courses differed.** In the game he is hit again every immunity window until something kills the zombie, and that difference is the entire value of intervening. So a hit now costs the actor its damage, makes it immune for its own window, and the scan resumes after that window against the same trajectories; an actor whose accumulated hits exhaust its life stops, because nothing further can be taken from it and charging a course for harm to somebody the same forecast has just said is down would make a hopeless fight read as infinitely expensive.

**The windows are the game's own, read out of the decompiled source rather than remembered**, because a number that is nearly right here is invisible. They are facts of the world, not tunables:

```
body        ordinary hit            a hit landing for 1      source
player      longInvince ? 80 : 40   longInvince ? 40 : 20    Player.Hurt, the cooldownCounter == -1 arm
companion   30 (20 for type 548)    the same, no branch      NPC.BeHurtByOtherNPC
```

A special hit channel chosen by the melee geometry writes `hurtCooldowns[channel]` rather than `immuneTime` and sets the same numbers, so one pair covers both routes, and `longInvince` is read as a flag rather than folded into a constant so a Cross Necklace changes the cadence without anything in the forecast knowing why. **The one-damage branch is carried rather than rounded away, because it is the quantity this forecast exists to measure**: an armoured player whose defence floors a weak hostile at a single point is hurt twice as often as the same player taking real damage, and pricing both at the long window would understate exactly the case where a persistent threat is most survivable and least worth abandoning a job for. `CapturedContactVictim` keeps the current immunity's remaining run and the window a fresh hit would grant as two fields deliberately, because the first says when the next hit can land at all and the second how often hits can land after that — a forecast holding only the first can price one hit and never a cadence.

**Knockback is not modelled, and that makes the cadence an upper bound rather than an estimate.** A real hit shoves the victim, so the next contact comes later than the window alone says, and the captured geometry is a frozen per-tick trajectory that cannot be re-simulated from inside the forecast. The bound lands in the direction that matters least: the objective reads the *difference* between a course that removes the threat and one that does not, and the kill truncation is exact, so an over-fast cadence scales both sides of the comparison rather than tilting between them. Modelling the shove wants the victim's knockback resistance and the hit's own direction, both of which belong to the native producer, and that is the next thing to build here.

The three fixtures that asserted `TailUnresolved` where the only cause was the missing successor are each a sharper answer now rather than a loosened one: a body hit at tick 13 and immune for thirty cannot be hurt at ticks 14 or 15, so reporting those as unknown would charge a course for uncertainty about a window whose answer is known. An actor whose immunity expires *inside* a short trajectory still reports unresolved, and `VerifyProjectionContracts` keeps that. Two rows stop the change being a licence to invent hits: the cadence row requires hits at 0, 30, 60 and 90 with life reading 100, 75, 50, 25 and requires the fifth not to appear, and the branch row runs one scene at one damage and at ten and requires 0, 20, 40, 60, 80 against 0, 40, 80 — asserted as the pair rather than as one number, because the value of the branch is the difference and a row on the long window alone would pass against a model that had lost the short one.

**It applies projected enemy kills, since 21 September 2026.** A `ContactThreat` carries the tick the evaluating course's own effects say that hostile dies on, and from that tick it makes no contact with either actor. The kill is a truncation and never a reward, and the two are different claims of which only one is true: expressed as a bonus it would be paid for a hostile that was never going to touch anybody, while a truncation is worth exactly the harm it removes — nothing when the hostile was harmless, a great deal when it was about to reach the player. A truncated tick is a resolved answer rather than a gap, so it does not make the tail unresolved; reading it as missing geometry instead would leave a course that clears the room permanently unable to be better than one that walks past it. Projectiles are still not forecast.

## Survival-first is a rule between fights, never a term an idle course can win on

`NominalOrder` in `CompareCourseOutcomes.cs` compares companion harm before anything else during a recognised encounter: between two courses that both take the fight, the one the companion survives wins even when it kills less. Applied with no qualifier that also said doing nothing beats any fight costing a single point — a course with no effects has no harm, so for an idle course against a fight `F` the comparison reduced to `F.CompanionHarm.CompareTo(0)`, positive whenever the fight cost anything at all. `SearchCourseOrders` runs this comparison against its incumbent best on every priced order, so during any recognised encounter an empty order outranked every fight that could be hurt — the plan's own G13 mutation, `idle artificially wins by zero damage`, found live by lane G's own fixture on 22 September 2026 rather than left as a hypothesis.

The fix is a qualifier, not a bonus: the rule fires only between two courses that are both fights. `CourseValue.TakesHostileLife` reads the *claimed* amount rather than the presence of a combat step, because the census caps each effect at the need's remaining amount, so a step whose target an earlier step in the same order already killed claims nothing and is not a fight by this test. Feasibility is not this field's job either — an unresolved prefix is refused by `Compare` before ordering runs, and native admission belongs to the binder — so what this rule establishes is only that the projection priced a real claim on a life.

This removes a tie-break rather than granting combat a bonus, and it holds on all three edges: a fight worth a great deal that takes a small hit now beats standing still; between two fights the safer one still wins though it is worth less (the arm that reddens if the encounter key is deleted rather than qualified); and a fight worth less than nothing still loses to standing still, on the total, exactly as before. On the 22 September capture's play-measures replay the residual `share of wanted-fight ticks the companion was not fighting on` moved from 39.894% (302 of 757) to 38.705% (293 of 757) — nine ticks, because that capture holds one recognised encounter's worth of pressure and the defect only fires while `EncounterIntensity > 0`. What the fix is worth is invisible in a quiet cave and would be the whole difference in a blood moon, which nobody has replayed.

## The search keeps what the winner beat

**`SearchCourseOrders` retains the best order whose *first step* differs from the winner's, as `RunnerUp` and `RunnerUpValue`, and `DecideCourseEachTick.LastRunnerUpOrder` surfaces it as purposes and a nominal worth.** The recorder's `task_order_runner_up` column reads it since the wave-1 merges of 22 September, as `purpose>purpose@value` or `-` when fewer than two distinct first steps were priced; a capture from between `0bb2c8a` and those merges carries `unavailable:the-search-retains-only-its-best-order` instead. What that column is for is the question the play of 0.38.13 left open on every tick of its last twenty-five seconds: whether a fight lost narrowly or was never on the board.

The first step is the discriminator rather than the whole order, because the first step is the only part of an order the tick performs: two orders that begin the same way are one answer to what the tick would otherwise have done. It is kept as a best-per-first-step table because the search discards everything it does not win with as it goes, and the runner-up is **recomputed from that table on first read and cached until the next priced order** rather than carried forward, since the winner can change under the search and a runner-up maintained against a moving winner is the order that used to be second. Pricing an order only marks the answer unsettled; the scan runs when somebody asks, so the column costs one scan per decision rather than one per order, which it did until a review on 22 September 2026 pointed out that k orders were each computing the same answer and discarding k−1 of them. The empty order sits in a slot beside the table rather than under a sentinel key: a dictionary refuses a null key, and a sentinel is a key some real opportunity could one day collide with.

Null is a real answer and not a missing one. A search that priced fewer than two distinct first steps had no alternative, and `Tools/EngineReplay/DecisionMaking/VerifyTheSearchRetainsItsRunnerUp.cs` holds both halves — that two orders leave a runner-up starting elsewhere, and that one leaves none.

## A purpose nothing can perform is refused before it is ordered, and that is a proven refusal

**`SearchCourseOrders.Begin` drops every usable opportunity whose purpose is absent from `ExecuteCourseBinding`'s executor map, and counts it as `step-purpose-has-no-executor`.** The map is the single fact of which purposes a course may bind; five are executable (`fire`, `mine`, `chop`, `collect`, `light`) and `break-pot` is deliberately not.

It is refused at `Begin` rather than inside the projection because an unexecutable opportunity can sit at any position of any order: filtering the candidate set removes it from every order at once, where a per-step check would have to run inside each projection and would still admit an order until it reached that step. And it is a **proven** refusal rather than the middle value, which is the distinction this tree spends most of its care on everywhere else: the map is a fact of the source tree, so no later slice, no larger allowance and nothing about the world can turn the answer into a yes. Reading it as unresolved would park the opportunity for ever and re-offer it on every observation, which is the starvation shape the three-valued rule exists to prevent.

**The defect it closes is a pot, and the class is much wider than a pot.** `break-pot` mapped to the empty string and `DecideCourseEachTick.Carry` read the blank as "no activity change" rather than as a refusal, so the search could order a dedicated trip to a pot and the tick would carry it. Measured whole-tick on the lighting scene while the light census was briefly over-bounded: thirty consecutive ticks of `bound=pot-target:tile:27,58 action=none`, the body travelling to a pot with no activity, no attempt and no credit, before the lighting trip the row was about could start. Nothing was red, because every part of that is a legal state read on its own — an activity name may be empty, a course may bind any purpose, and a trip to a real opportunity is what the search is for. It was invisible for a second reason too: until the census was bounded the light flood crowded the pot out of discovery entirely, so the path existed and nothing could reach it.

The general form is the one to carry: **a domain that gains discovery before it gains an executor fails silently and looks like a companion that decided something and then stood there.** Discovery, binding and execution are three migrations and a domain can complete the first two and not the third, which is the same shape as a source with no binder one layer up (`Opportunities/CLAUDE.md`) and a capture with no coverage fact one layer below.

**A structural refusal is tallied apart from an evidence refusal, and mixing them silenced a tripwire for a day.** `SearchCourseOrders` keeps two dictionaries: `Refusals`, which is why an order was thrown away given what the observation *held* — `target-capture-missing`, `assistance-target-unresolved` and their kin — and `StructuralRefusals`, which is why an order could never have been built at all, today holding only `step-purpose-has-no-executor`. The split exists because `AuditDecisionContracts`' second contract, `empty-course-beside-usable-work`, fires only when every refusal reason is one of the two not-observed strings: with the executor reason in the same tally, any decision that admitted a usable pot made that test false, so the contract could not fire on the mixed case it exists for — a settled empty course beside a usable light site *and* a refused pot. The recorder writes them apart too, as `refused:` and `structurally-refused:`, and only the evidence reasons are subject to the top-four cut, because a structural reason crowded out of the payload takes the audit's own inputs with it. The rule for a reason added later: if no larger allowance, no later slice and nothing about the world could change the answer, it is structural; otherwise it is evidence.

**A pot is ordered now, because the owner ruled on 23 September 2026 that a pot is a collection task.** From 22 to 23 September a pot was discovered, admitted and never ordered, on the reading that it was only ever broken in passing; the ruling reversed that, so the census publishes a pot under `collect-target` with the purpose `break-pot`, collection declares that domain, and a bound pot is a trip collection performs — reserving the hand on arrival, opening and concluding an attempt credited to collection, which is exactly the list this paragraph once gave for "a future pot executor". A pot in reach is still broken in passing, but through a one-step binding the course accepts (`DecideCourseEachTick.AcceptIncidental`) rather than by a scan acting on its own. The defect above stays closed by construction: the executor map is derived from the activities' own `CourseDomains`, so a domain nobody performs cannot be bound, and `Tools/EngineReplay/Assistance/VerifyAssistanceTrips.cs`'s `J08 a pot the course binds is a trip collection performs` fails by name if a bound pot flies the body with no attempt behind it.

**Two rows pin it and they are deliberately different kinds.** `G01 every purpose discovery can publish has an executor or a written exemption` is pure: it sweeps `Companion/` for every file that mints an `OpportunityKey`, refuses a minter it does not know, asserts each of the six purposes is still a literal in the file it is attributed to, and then requires each to have either an executor the brain registers or an entry on a written exemption list carrying its ruling. `J08 a pot is never a course step of its own, however little else there is to do` is whole-tick: torch placement off, both work policies disabled, nothing else in the world, so the pot is the only usable opportunity and wins any comparison it is allowed to enter — with a premise that the census did admit it, because a scene where the pot is never admitted would pass while proving nothing. Restoring `["break-pot"] = ""` reds all three of them.

## A fact costs what it is asked for, not what it might be asked for

**A `DecisionFact` is its four fields and nothing else, since 22 September 2026, and it got there in two steps that are worth keeping apart.** It used to compute a canonical JSON form and a SHA-256 of it in its constructor; making the pair lazy measured 1,387 bytes a fact eagerly against 112 lazily, a factor of 12.4, for a JSON string, its UTF-8 bytes, a hash and a hex string that most facts in a snapshot are never asked for. Deleting the pair took that to **96 bytes a fact**, which is the two backing references at eight bytes each and is the arithmetic confirming nothing else went with them. The play of 0.38.13 carried 1,603 facts in its frozen observation at about thirty-eight decisions a second, which **extrapolates** to roughly two megabytes a decision and seventy-seven a second: that figure is the per-fact measurement multiplied by a fact count from a capture nobody re-ran, not a rate anybody observed, and it assumes no fact is digested — which for two days it was not true of, below. The same session counted 813 gen-0, 357 gen-1 and 50 gen-2 collections in a minute, with the allocation rate doubling as the fact count grew and 29 of the 37 worst frames coinciding with a gen-2 collection at 45 to 70 ms of brain each.

The fields are immutable, so a value computed twice is the same value, and there is deliberately no lock: the worst a race could do is build an identical string twice, and the brain is single-threaded.

**Laziness alone recovered only three-quarters of that, and the last quarter was `TrackedFactReader.Read`.** A review on 22 September measured a 500-decision scene and found 4,329 of its 16,200 snapshot facts — 26.7% — still serialised and hashed, because every tracked read took `fact.Digest` to record it. So the rule that fixed the other comparisons was applied to the read as well: **compare the fields, not the hash, whenever you hold both facts.** The digest is a hash *of* version, evidence and value, so a field comparison is what a digest comparison was approximating and is strictly stronger than it, since a hash can collide and a field comparison cannot. `FactRead` records a `FactValue` and a `FactEvidence` instead of a hex string, and `FactRead.Matches` compares exactly the three fields the hash was over; `DecisionFactSnapshot.IsModelExtensionOf` had stopped digesting the whole previous catalogue on every model answer (1,600 facts times a travel query on most bindings) and `DiscoverAssistanceOpportunities` its examined prefix on every slice.

**`DecisionFact.Digest` and `CanonicalValue` are gone**, later the same day, once that read was the last caller: a lazy field with no caller is not free of cost so much as free of evidence — the next reader has no way to tell a token something needs from one nobody has asked for since it was written. The need they were kept for, a stable cross-process token for a *recorded* capture that cannot compare fields it did not store, was already served by `CaptureDecisionSnapshot.Digest(string)` over the stored value text, which is the only digest in the tree now. `SameObservationAs` is a fact's only equality.

**The frozen observation's growth is explained, it was not a leak, and it is bounded now.** It was written up as "150 to 1,603 with no fall-back", which reads as a set nobody clears, and the world run over the 22 September capture says otherwise. Counting the observation by fact kind on every one of the 2,340 ticks (`Tools/WorldRun/CountTheFrozenObservationByKind.cs`, behind `AIC_FACT_KINDS`), the total ran 12 to 1,637 and **`light-target` dominated every other kind by two orders of magnitude**, with `mine-target` at 13 and `combat-use` at 6 to 11 across four runs of one tree. The count was near-monotone, which is what made a leak the natural reading.

**Every figure in this paragraph is a live-brain sample and carries its run**, which is the rule `Tools/WorldRun/CLAUDE.md` states and which the first version of this paragraph broke three lines away from stating it. Across four runs of the same commit the per-kind maxima were stable — `light-target` 1,599 in three of them — and everything derived from *how the run went* was not: falls in 2,340 ticks read 21, 69, 55 and 57, and the final totals 1,582, 1,584, 1,588 and 1,582. A single one of those quoted as a fact is a sample wearing a measurement's clothes.

**The bounding box is what refutes it**, and it is the measurement a per-kind count could not have replaced: the published light sites span exactly 125 tiles across — the work window's own width — and the box's minimum corner tracks the player's intent region tick for tick, so at tick 2,101 it runs 3,423 to 3,547 with the heading at 3,485 and holds nothing from the window at tick 301, which began at 3,191. The census re-sweeps a moving window and drops everything the window leaves; what grows is the *darkness fraction* of a fixed 125×125 square as the player descends from a lit surface into a cave, from a five-row band to the whole square. A set that accumulated and one that re-sweeps a descending window both produce a rising number, and only the corner moving tells them apart.

So the declared bound of 512 was the thing that was wrong, and it was wrong in a way a single total cannot fix: the largest kind in a healthy snapshot is legitimately window-sized, so the tripwire fired on the healthy kind — 470 to 647 times a run across four runs of one tree — while a runaway in `combat-use` at three or four hundred would have sat invisible behind it. **`AuditDecisionContracts.MaximumFactsOfKind` is per kind now**, with lighting's taken from what the census can publish and a flat 256 for everything else, and `VerifyDecisionTripwires`'s third arm is the case the total could not see: a healthy light census beside a combat runaway, summing to less than 512.

And the cost was real and co-located: `decide-overran-allowance` fired 8 to 31 times a run, almost all after the tick where `light-target` passed 500, because discovery spends one allowance unit, two tracked reads and one JSON deserialise per site. Regressed over a whole replay, **decide_ms ≈ 3.505 + 0.003813 × sites** — 5.9 ms of a 12 ms allowance at 1,540 sites, before the search prices anything, and the search never priced more than three orders in one decision over those 2,340 ticks. `RankCensusSitesByWorth` is what closed it, and the section below is the rule it applies.

**The older guard stands where the explanation used to be, and its own limits are unchanged.** `Tools/EngineReplay/DecisionMaking/VerifyWhatEachDecisionCosts.cs` holds the bound and its own limits: a seventy-tile ore seam walked end to end peaks at 46 facts and *falls* to 29 as the census window leaves the ground behind, and a crowd of eight hostiles peaks at 54 with the combat front contributing at most 36 use facts. So neither the mining census nor the combat front accumulates, and what grew tenfold in play is most likely the honest size of a real world's censuses rather than a leak — which is a statement about what was eliminated rather than an answer.

## The objective suppresses work under danger, and the term standing in for defence survived its own deletion condition

`CourseComparisonEpisode.RelevanceFor` in `CompareCourseOutcomes.cs` charges a non-combat need `1 − max(urgency, intensity)` and leaves a hostile's life whole. **The max rather than the product is the whole of why it is one term and not two factors.** A boss fight raises the player's danger *and* the encounter, so multiplying would charge one situation twice and price a wounded player in a blood moon at a quarter of what either alone says; taking the larger reads them as two views of one danger, which is what they are. Written the other way round — a bonus on combat — the same ordering would need a magnitude nobody could derive, and every tuning of it would move work's value too.

Encounter intensity joined urgency here on 21 September 2026, and **the shape of how it was missing is worth more than the term**: the episode was handed the encounter as a boolean, because `DecideCourseEachTick` collapsed the sense's ramping 0..1 reading to `Intensity > 0` on the way in, and the objective correctly refused to treat a boolean as an intensity of one — that would zero every optional need the instant inferred pressure existed at all, where the ramp is exactly what keeps a busy cave from reading like a blood moon. So a field that lost precision at one seam silenced a whole preference two files away, with a reasoned comment at the far end explaining why the term could not be written. The episode takes the double now and derives the boolean from it, which is the direction that cannot lose anything, and it refuses a reading outside 0..1 rather than clamping, because an off-scale value is an adapter defect and a clamp turns it into a plausible number nobody questions.

**The term's deletion condition was tested rather than assumed on 21 September 2026, and it survived for a reason that is no longer the reason written on it.** The condition read "when contact harm models repeated hits"; that model landed one commit earlier, so the measurement was taken. Single-variable on the same `danger lifts combat over work` scene, with the urgency half removed and the encounter half left standing:

```
with the term      combat takes 109 of 120 ticks
without it         combat takes   0 of 120 ticks
```

## Three things the family chooser measured about pricing a job, carried here when it was deleted

The retired utility scorer priced each activity as a product of named factors, and `../CLAUDE.md` carried what those factors had learned in play. `AIC-419` deleted the scorer on 22 September 2026, so the measurements move here or stop existing; each is written as what the course does, with the chooser's own number beside it, because a property kept only as history comes back as a patch wearing new mechanics.

**A job's duration is the course's own projection and never the activity's report of its own length.** The chooser multiplied a task candidate by `window / (window + ticks until done)` and took those ticks from `CompanionAction.ForecastTicks`, so an activity that inherited the base class's zero was scored as instant: the lighting trip of 218 ticks outbid a slime hunt that reported its flight honestly, which is the defect the time term was built on. That class cannot be expressed here. Nothing in `Courses/`, `Opportunities/` or `DecideCourseEachTick` reads `ForecastTicks` or `TaskTicks` — searched across all three on 2026-09-22, zero hits — and an order's clock is `ReadCourseTravel`'s captured route timing plus the use duration the projection holds, both of them facts a binder must declare and a manifest must carry. `Tools/EngineReplay/DecisionMaking/VerifyWholeCoursePricing.cs`'s `a non-empty course is priced end to end from the tick it starts at` is the row: a long step pays the harm and the companionship gap a long step accumulates, rather than a multiplier the activity chose for itself, so there is no number for an activity to under-report.

**Neither an unknown route nor an absent one reads as free, and a way home has three answers rather than two.** The chooser reached this by hand in `Chooser.RouteDetour`, in two arms a caller could get wrong: an unfinished flood priced the straight-line gap as a floor the real route can only exceed, and a player's tile a finished flood proved absent read twice the straight line, which is the disc's own guarantee that no route to a place it proved absent is shorter than about three times its straight line. Both arms were a consumer reconstructing what a typed answer gives this tree for nothing, which is the same reason the light and reach senses answer in three values — and here the type has a third value the chooser's arithmetic had no room for, because a travel fact that has not arrived yet is a different thing from one that arrived saying no.

**This core is the live brain, not an integration in progress.** Since `0bb2c8a` the tick calls `DecideCourseEachTick` and a published course's bound step supplies the position request, so every contract on this page describes what the game runs.
